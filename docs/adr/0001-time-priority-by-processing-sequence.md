# ADR 0001. 시간 우선 기준은 종목 워커의 처리 순번

- 상태: 채택 (2026-11-09)
- 관련: IMPLEMENTATION_GUIDE §5.2, §5.4

## 맥락

가격-시간 우선 체결에서 "시간"을 무엇으로 정할지 정해야 한다. 후보는 HTTP 도착 시각, 주문 ID(AUTO_INCREMENT), 종목 워커가 처리한 순서다.

HTTP 요청 스레드는 여러 개이므로 도착 시각, ID 발급 순서, T1 커밋 순서, 대기열 전달 순서가 서로 다를 수 있다. 주문 ID는 INSERT 시점에 발급되고 커밋은 그 뒤에 일어나므로, 작은 ID가 더 늦게 대기열에 들어갈 수 있다.

## 결정

시간 우선 기준은 **종목 워커가 주문을 처음 처리한 순서**다.

- 워커는 주문을 처음 처리하는 T2에서 종목별 처리 순번 `orders.seq`를 기록한다.
- 같은 가격의 대기 주문은 `seq`가 작은 주문이 먼저 체결된다.
- 부분 체결 뒤에도 `seq`는 바뀌지 않는다. 원래 우선순위를 유지한다.
- 종목별 `seq`는 `UNIQUE(symbol_code, seq)`로 중복을 막는다.

## 근거

- 종목당 워커가 하나이므로 처리 순서는 하나로 정해지고, 그 순서가 곧 호가창의 실제 상태 변화 순서다.
- 접수 순서를 엄격히 보장하려면 접수, 커밋, 대기열 전달을 하나로 묶는 추가 설계가 필요하다. 현재 범위에서는 이득보다 비용이 크다.

## 결과와 비용

- 사용자가 먼저 HTTP 요청을 보냈더라도 다른 주문보다 늦게 처리될 수 있다. 이 시스템은 "HTTP 도착 순서"를 보장한다고 주장하지 않는다.
- 주문 ID 정렬로 시간 우선을 판정하는 프로토타입 `OrderMatcher` 방식은 가져오지 않는다.

## 검증

- 단위 테스트: 같은 가격에서 `seq` 순서대로 체결, 부분 체결 후 순번 유지.
- 복구 테스트: 재기동 후 잔여 주문의 우선순위가 재기동 전과 같다.

## 재검토 조건

접수 순서를 시간 우선 기준으로 요구하는 요구사항이 생길 때.
