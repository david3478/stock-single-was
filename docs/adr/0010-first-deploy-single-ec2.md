# ADR 0010. 첫 배포는 EC2 한 대에 앱과 MySQL을 함께, 내 IP만 접속 허용

- 상태: 대체됨 (2026-11-27, ADR 0011)
- 관련: IMPLEMENTATION_GUIDE §8, §9, §13

## 맥락

다음 멘토링 목표는 "실행 가능한 시스템"이다. 인계서는 AWS 측정에 별도 RDS MySQL을 권장한다.
지금 필요한 것은 성능 측정이 아니라 브라우저에서 주문·체결이 돌아가는 것을 보여주는 것이다.
데모에는 로그인이 없어 누구나 아무 계좌로 주문할 수 있다.

## 결정

1. 첫 배포는 EC2 한 대에서 `deploy/compose.yml`로 앱 컨테이너와 MySQL 컨테이너를 함께 실행한다. MySQL 포트는 외부에 열지 않는다.
2. 프론트는 Spring이 정적 파일로 함께 제공한다. 별도 프론트 서버나 Nginx는 두지 않는다.
3. 보안 그룹은 HTTP(80)를 내 IP에서만 허용한다. SSH 포트는 열지 않고 SSM으로 접속한다.
4. 이미지는 ECR에 Git SHA 태그로 올린다. 첫 배포는 손으로 하고, 성공한 절차를 GitHub Actions(OIDC + SSM)로 옮긴다.
5. DB 비밀번호는 EC2의 `deploy/.env`에만 둔다. git에 올리지 않는다.

## 근거

- 인스턴스 하나, 보안 그룹 하나로 끝나서 실패 지점이 적다. RDS 생성·서브넷 그룹·보안 그룹 연결을 첫 배포에서 뺀다.
- RDS는 중지해도 7일 뒤 자동으로 다시 켜져 비용이 계속 나간다.
- 앱과 DB가 같은 머신이라 측정값은 의미가 없지만, 이번 배포는 측정용이 아니다.

## 결과와 비용

- EC2가 사라지면 DB 데이터도 사라진다. 데모 데이터는 seed로 다시 만들 수 있으므로 받아들인다.
- 앱과 MySQL이 메모리를 나눠 쓴다. t3.small(2GB) 이상을 쓰고 JVM 힙 512MB, InnoDB 버퍼 256MB로 제한한다.
- 다른 사람이 접속해야 하면 그 IP를 보안 그룹에 추가해야 한다.

## 검증

- 로컬에서 같은 `deploy/compose.yml`과 이미지로 앱을 띄워 주문·체결이 되는지 확인한다.
- EC2 배포 후 브라우저로 매도 → 대기, 매수 → 체결 완료를 확인한다. 등록하지 않은 IP에서는 접속되지 않아야 한다.

## 재검토 조건

QAS 측정(10단계)을 시작할 때. 이때는 DB를 별도 서버(RDS 또는 별도 EC2)로 분리하고 부하 생성기도 다른 머신에서 실행한다.
