# ADR 0002. 재기동 시 처리 전 주문은 주문 ID 순으로 복원

- 상태: 채택 (2026-11-09)
- 관련: IMPLEMENTATION_GUIDE §5.4, ADR 0001

## 맥락

재기동 시 `RECEIVED`(접수 확정, 처리 전) 주문은 아직 `seq`가 없다. 대기열에 다시 넣을 순서를 정해야 한다.

## 결정

종목별로 `RECEIVED` 주문을 **주문 ID 오름차순**으로 대기열에 복원한다. 처리 순번은 복원 뒤 워커가 처리할 때 ADR 0001에 따라 새로 부여한다.

## 근거

- 재기동 시점에는 이전 프로세스가 종료되어 커밋되지 않은 T1은 롤백된 상태다. 복구 조회는 커밋된 `RECEIVED` 주문을 빠짐없이 읽는다. 누락 문제는 없고 순서만 정하면 된다.
- `RECEIVED` 주문은 아직 어떤 체결 결과도 확정되지 않았으므로, 장애 전 대기열 순서와 달라져도 이미 관찰된 결과와 모순되지 않는다.
- 주문 ID는 DB에 남아 있어 재현 가능한 정렬 기준이다.

## 결과와 비용

- 장애 전 대기열 안의 순서와 복원 순서가 다를 수 있다. 이 차이는 의도한 동작으로 문서화한다.
- **주의**: 이 정렬은 "프로세스가 멈춘 뒤 한 번 읽는" 복구에서만 안전하다. 서버가 동작하는 중에 `id > 마지막 ID` 커서로 `RECEIVED`를 반복 조회하면, 늦게 커밋된 작은 ID를 건너뛴다. 런타임 조회는 ADR 0005를 따른다.

## 검증

- 장애 테스트: T1 커밋 후 대기열 전달 전에 종료 → 재기동 → 해당 주문이 처리된다.
- 복구 순서 테스트: 여러 `RECEIVED` 주문이 ID 순으로 처리되고, 기존 잔여 주문의 `seq`보다 큰 순번을 받는다.

## 재검토 조건

체결 서버를 분리해 복구 중에도 다른 프로세스가 주문을 접수할 수 있게 될 때.
