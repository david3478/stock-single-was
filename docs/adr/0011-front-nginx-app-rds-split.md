# ADR 0011. 프론트는 Nginx 컨테이너, 앱은 API만, DB는 RDS로 분리

- 상태: 채택 (2026-11-27)
- 관련: ADR 0010(대체), IMPLEMENTATION_GUIDE §8, §9, §13
- ADR 0010을 대체한다.

## 맥락

ADR 0010은 첫 배포를 EC2 한 대에 앱과 MySQL을 함께 띄우고, 화면 파일은 Spring이 정적 파일로 제공하기로 했다.
그 배포는 실행하지 않았고, 시연 시점이 멀어 6단계(SSE)를 먼저 끝냈다.

이 시스템은 서버를 재시작하면 메모리 호가창을 DB에서 다시 복원한다. 화면 파일이 앱 jar 안에 있으면
CSS 한 줄을 고쳐도 앱을 재배포해야 하고, 그때마다 체결 엔진이 재시작된다.
또 10단계 측정에서는 DB를 앱과 다른 서버에 두어야 하므로, 앱과 MySQL을 한 서버에 두는 구성은 어차피 다시 만들어야 한다.

## 결정

1. 화면 파일은 `frontend/public/`에 두고 Nginx 컨테이너가 제공한다. Nginx 이미지에 파일을 넣어 ECR에 Git SHA 태그로 올린다.
2. Nginx는 `/api/*`를 앱 컨테이너로 넘긴다. 브라우저에는 주소가 하나라 CORS가 필요 없다.
3. SSE 경로(`/api/accounts/{id}/notifications`)는 응답 버퍼링을 끄고 읽기 제한 시간을 1시간으로 둔다.
4. Nginx와 앱은 같은 EC2에서 서로 다른 컨테이너로 실행한다. 앱은 외부 포트를 열지 않는다.
5. Nginx는 앱 주소를 요청마다 Docker DNS로 다시 찾는다. 앱 컨테이너만 재배포해 IP가 바뀌어도 Nginx를 재시작하지 않는다.
6. DB는 RDS MySQL 8.4. 퍼블릭 접근을 막고, 보안 그룹은 EC2 보안 그룹에서 오는 3306만 허용한다.
7. 로컬 개발은 `local` 프로필에서만 Spring이 `frontend/public/`을 제공한다. 운영 jar에는 화면 파일이 없다.
8. `/actuator`는 Nginx로 열지 않는다.

## 근거

- 화면 배포(Nginx 이미지 교체)와 체결 엔진 재시작이 분리된다.
- Nginx를 같은 EC2의 컨테이너로 두어도 위 목적은 달성된다. 별도 서버는 비용만 늘린다.
- 같은 주소로 묶으면 SSE와 이후 쿠키 인증에서 CORS를 다루지 않아도 된다.
- 이미지에 화면 파일을 넣으면 떠 있는 버전이 태그로 드러나고, 롤백은 태그만 바꾸면 된다.
- Nginx는 기본으로 응답을 버퍼에 담고, 넘치면 임시 파일에 쓴다. 끝나지 않는 SSE 스트림에는 맞지 않아 끈다.
  로컬 실측(Nginx 1.27)에서는 버퍼링을 켜도 알림 지연이 없었으므로, 지연 방지를 근거로 삼지 않는다.
- Nginx 기본 읽기 제한은 60초라, 조용한 SSE 연결을 끊고 재연결이 잦아진다.

## 결과와 비용

- RDS는 중지해도 7일 뒤 자동으로 다시 켜진다. 쓰지 않을 때는 스냅샷을 남기고 삭제한다.
- 배포할 이미지가 둘(앱, 프론트)이 된다. 프론트만 바꿀 때는 프론트 이미지만 올리고 Nginx 컨테이너만 교체한다.
- 로컬 개발 중 화면은 Spring이, 운영에서는 Nginx가 제공한다. Nginx 설정(SSE 버퍼링 등)은 로컬 검증용 compose로 확인한다.

## 검증

- 로컬에서 `deploy/compose.yml` + `deploy/compose.local-db.yml`(RDS 대신 MySQL 컨테이너)로 Nginx를 거쳐 화면, API, SSE가 동작하고 SSE 알림이 즉시 오는지 확인한다.
- AWS에서 같은 이미지로 RDS에 붙여 주문·체결·SSE 알림을 확인한다. 등록하지 않은 IP에서는 접속되지 않아야 한다.
- 앱 컨테이너만 재배포한 뒤 Nginx 재시작 없이 API가 다시 동작하는지 확인한다.

## 재검토 조건

- HTTPS와 도메인이 필요할 때(ALB 또는 Nginx 인증서).
- WAS를 여러 대로 늘릴 때. 이때 Nginx 또는 ALB가 부하 분산을 맡고, SSE 연결 목록과 신호 전달 방식을 다시 정한다.
