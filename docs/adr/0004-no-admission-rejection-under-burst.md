# ADR 0004. 순간 폭주에서 접수 단계 혼잡 거절을 하지 않는다

- 상태: 채택 (2026-11-09)
- 관련: IMPLEMENTATION_GUIDE §5.1, §10 QAS 3, ADR 0005

## 맥락

QAS 3은 10초간 3,000/s(한 종목 2,000/s, 나머지 9종목 합계 1,000/s)를 보내고, 처리 결과(체결 또는 대기 등록)를 2초 안에 받지 못한 비율이 0.1% 미만이어야 한다. 정상 주문의 혼잡 거절도 실패로 계산한다.

## 결정

- 정상 주문을 대기열 혼잡을 이유로 접수 단계에서 거절하지 않는다.
- 종목별 대기열은 상한을 두되 **메모리 안전장치**로만 쓴다. 상한을 넘어도 접수는 성공하고, 넘친 주문은 DB의 `RECEIVED`에서 이어서 읽는다(ADR 0005 ①).
- 초기 상한은 종목당 50,000건으로 둔다. QAS 3에서 한 종목에 들어오는 최대 20,000건보다 크다. 대기열에는 주문 ID 수준의 작은 객체만 담는다.
- QAS 3은 HTTP 접수 응답이 아니라 **SSE 처리 결과 이벤트의 도착**까지를 측정한다.

## 근거

- 거절은 QAS 3 판정에서 어차피 실패이므로 점수를 지키는 수단이 아니다. 거절이 보호하는 것은 서버 메모리뿐이다.
- 접수된 주문은 DB에 확정되어 있으므로, 대기열이 넘쳐도 버리지 않고 나중에 처리할 수 있다.
- 적체를 그대로 두고 측정하면 대기열 체류 시간이 실패의 원인으로 드러난다. 이후 개선 실험의 근거가 된다.

## 결과와 비용

- QAS 3의 통과 여부는 대기열 크기가 아니라 **폭주 종목 워커의 처리량**이 결정한다. 폭주 종목에서 실패를 거의 내지 않으려면 그 워커가 약 2,000건/s를 처리해야 한다. 주문당 T2 커밋 시간이 약 0.5ms 이하라는 뜻이다. 건별 커밋인 기준선은 이 조건을 충족하지 못할 가능성이 높고, 이 경우 마이크로배치 실험으로 이어진다.
- 폭주 종목의 T2가 DB 커넥션 풀을 차지하면 다른 종목도 느려질 수 있다. 커넥션 풀은 `종목 워커 수 + HTTP 요청 여유분` 이상으로 잡고, 다른 9종목의 지연을 따로 집계한다.
- 접수 과부하(예: DB 커넥션 고갈)로 T1 자체를 실행할 수 없을 때는 503을 돌려준다. 이것은 "접수 전 실패"이며 QAS 3에서 실패로 계산한다.

## 검증

- QAS 3 측정에서 종목별 대기열 길이, 대기열 체류 시간, T2 커밋 시간을 시계열로 기록한다.
- 마지막 주문을 보낸 뒤에도 각 주문의 2초 판정이 끝날 때까지 관찰한다. 부하 생성기의 미전송 건수도 기록한다.

## 재검토 조건

- 측정에서 대기열 메모리가 실제 위험으로 확인될 때.
- QAS 3 목표나 실패 판정 기준이 바뀔 때.
